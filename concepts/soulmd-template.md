## Definition

An agent operating contract that defines what an AI agent is, how it talks, when it pushes back, what it can do without asking, what it has to escalate, and what kind of work actually matters. SOUL.md is a living document, not a one-time prompt.

## Core Sections

- **Stance** — tone, pushback rules, accountability
- **Autonomy** — what requires approval vs. what the agent can do directly
- **Mission** — primary objective, active projects, needs-work areas, back burner
- **Tone & Communication** — private work vs. public-facing work
- **Operating Mode** — orchestration vs. direct execution, delegation rules
- **Standards** — what good output looks like, escalation rules
- **Self-Improvement** — extract lessons, preserve corrections, automate repeats

## Key Insight

Most people prompt agents like chatbots. "Helpful assistant" is not an operating model. A serious agent needs role, mission, boundaries, standards, permission to act, and permission to stop you from wasting your own time.

The mismatch: expecting operator behavior from assistant instructions.

## When to Use

When setting up a new agent or redefining the relationship with an existing one. Customize the agent name, primary objective, active projects, tone, autonomy boundaries, and escalation rules.
