# Buzz

Buzz is the source-described open-source workspace from Block that puts people, agents, conversations, and code on the same level behind one cryptographic identity system. Its stated goal is to reduce the context loss and tool dependence created by splitting work across chat, code hosting, CI, and agent tools. Product capabilities and roadmap statements below remain source-reported.^[raw/articles/xarticle-why-were-buzzing-2080056638820450400.md]

## Architecture and operating model

Buzz stores messages, patches, reviews, workflow steps, and approvals as signed events on a relay that the operator hosts. People and agents receive the same kind of identity — keys, channels, and an audit trail — so an agent can search history, open repositories, send patches, review code, run workflows, and edit canvases as an attributable team member. ^[raw/articles/xarticle-why-were-buzzing-2080056638820450400.md]

The announcement lists three principles: self-sovereignty through owned relays, domains, data, and portable keys; openness through Apache 2.0, Nostr, model agnosticism, and harnesses for Goose, Codex, and Claude Code; and one context, where a feature branch becomes a channel and patches, CI, review, conversation, and merge decisions share a permanent thread. ^[raw/articles/xarticle-why-were-buzzing-2080056638820450400.md]

## Status and open work

The source says channels, threads, DMs, canvases, media, search, an audit log, workflows, and a desktop app work today, while full Git hosting is still being wired up. Mobile, push, and more complete approval gates are described as forthcoming or partial. Each workspace currently uses a single relay; federation is presented as the clearest path toward the design's broader decentralization. ^[raw/articles/xarticle-why-were-buzzing-2080056638820450400.md]

The stated next problems are tighter agent scoping around private workspace data, a hosted option, token efficiency, an open workflow/agent ecosystem, and agents that can transact. Block's own increasing use of Buzz is named as the first test, with usefulness to other teams as the second. These are launch claims and plans, not independent adoption or performance evidence. ^[raw/articles/xarticle-why-were-buzzing-2080056638820450400.md]
