## Overview

Thariq's writing focuses on where the default Claude Code harness breaks down and how explicit artifacts, dynamic workflows, and unknown-discovery passes compensate. ### Effort-routing article (September 25, 2026)^[raw/articles/thread-trq212-2103576349499855160.md]

Thariq’s local thread frames Claude Code effort as a source-described control over verification, edge-case testing, and how much independent judgment Claude uses; it says changing effort does not break the prompt cache. The author’s normal software-engineering loop is: ask the model to interview for missing details, implement at low/medium effort, review the result at low effort as needed, then verify and test at high effort. The post names Fable 5.1, Opus 5.5, Terminal-Bench 3.0, and the `/effort` command; its benchmark and timing claims are source-described rather than independently reproduced.
