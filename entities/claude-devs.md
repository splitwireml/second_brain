# ClaudeDevs

ClaudeDevs is an X account publishing official/practitioner-facing [[claude-code]] guidance. Its July 2026 loop article, credited in the export to @delba_oliveira, translates Claude Code's loop vocabulary into an operator taxonomy: turn-based prompting, [[goal-primitive]] outcome loops, time-based `/loop` or `/schedule` cadences, and proactive routines that combine schedules, goals, dynamic workflows, and auto mode.^[raw/articles/xarticle-getting-started-with-loops-2074208949205881033.md]

A later article credited to @lydiahallie explains the orthogonal controls behind Claude Code output quality: model selection changes the frozen weights and capability tier, while effort changes how thoroughly the same model plans, reads files, verifies, and keeps pushing before checking in. The operational rule is to fix context first, then change the model when Claude did not know enough and change effort when it did not try hard enough.^[raw/articles/xarticle-model-and-effort-in-claude-code-knowing-more-vs-tr-2074900291062034618.md]

## Contribution to the wiki

- Clarifies that "loop" should be classified by trigger, stop condition, Claude Code primitive, and task fit rather than treated as one generic autonomy pattern.
- Connects loop quality to reusable verification skills, independent code review, bounded turn caps, model routing, and usage review.
- Adds a practical [[claude-code-model-effort]] distinction: larger models buy capability/knowledge, while higher effort buys more work, verification, and persistence inside the same task.
