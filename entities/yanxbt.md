## Loop architecture addition

A June 2026 follow-up mapped [[hermes-agent]] as an eight-loop runtime rather than a single prompt/response shell. The article's distinctive contribution is the nesting argument: core turns, `/goal`, self-improving skills, curator maintenance, persistent memory, Kanban dispatch, context compression, and sub-agent delegation all reinforce each other across different timescales.

It also sharpened the systems claim behind YanXbt's broader operating-system framing: Hermes compounds because procedure learning, memory persistence, orchestration, and context management are native loops inside one runtime rather than separate bolt-ons.
